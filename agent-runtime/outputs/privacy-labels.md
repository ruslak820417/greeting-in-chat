# QRChat — App Privacy Labels (App Store Connect)

**Date:** March 21, 2026
**App:** QRChat v4.0
**Bundle ID:** com.ruslan.qrchat

---

## Summary

QRChat is designed to collect the absolute minimum data required for functionality. Messages are end-to-end encrypted — the developer cannot read them. The server stores only transient encrypted blobs and anonymous push routing data.

---

## App Store Connect — Privacy Labels Configuration

### Does your app collect data?

**YES** — but only minimal functional data as described below.

### Does your app track users?

**NO** — QRChat does not use any tracking technologies (no IDFA, no advertising SDKs, no analytics, no cross-app tracking).

`NSPrivacyTracking` in PrivacyInfo.xcprivacy: `false`

## Data Types Collected

### 1. Identifiers

| Field | Value |
|-------|-------|
| **Data Type** | Device ID |
| **Specific data** | Anonymous mailbox ID (random 128-bit value, NOT derived from device ID or user identity) |
| **Linked to User** | No |
| **Used for Tracking** | No |
| **Purpose** | App Functionality (push notification routing) |
| **Collection method** | Generated on-device, sent to server during push token registration |

**Note:** The mailbox ID is a pure random value generated by `nacl.randomBytes(16)`. It is NOT derived from any key material, UDID, IDFV, or any other device/user identifier. The two-map architecture on the server (userId -> mailboxId, mailboxId -> pushToken) ensures no single data structure links push tokens to user identity.

### 2. Identifiers

| Field | Value |
|-------|-------|
| **Data Type** | Device ID |
| **Specific data** | APNs push token |
| **Linked to User** | No (stored mapped to anonymous mailbox ID, not user ID) |
| **Used for Tracking** | No |
| **Purpose** | App Functionality (offline message delivery notification) |
| **Collection method** | Provided by iOS, registered with server via WebSocket |

## Compliance Notes

### GDPR (EU)
- Minimal data collection satisfies data minimization principle (Art. 5(1)(c))
- No consent banner needed for core functionality data
- Privacy policy must be accessible from within the app (Settings screen)
- Data processing basis: Legitimate interest (push notification delivery)

### CCPA (California)
- QRChat does not sell personal information
- No targeted advertising
- Privacy policy must disclose categories of personal information collected

### App Store Review Guidelines (2026)
- Guideline 5.1.1: Data Collection and Storage — compliant (minimal collection, encrypted storage)
- Guideline 5.1.2: Data Use and Sharing — compliant (no sharing beyond service delivery)
- Guideline 5.1.3: Health and Wellness Apps — not applicable
- Guideline 5.1.4: Kids — not targeted at children, no data collected from minors
