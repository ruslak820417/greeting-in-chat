<objective>
Fix the audio session lifecycle for cold start incoming calls. Currently, when the app is woken by a VoIP push: (1) CallKit activates the audio session BEFORE the WebRTC peer connection exists, (2) CallScreen.tsx calls InCallManager.stop() to reset audio from previous calls, which DEACTIVATES the audio session CallKit just activated, (3) the WebRTC peer is created without an active audio session, causing silent calls.

Purpose: This is the primary "no audio on cold start calls" bug. The fix ensures InCallManager.stop() is skipped on cold start, and RTCAudioSession.audioSessionDidActivate() is re-called AFTER the peer connection is created so WebRTC can bind to the active session.

Output: Corrected audio session lifecycle in CallScreen.tsx + validated RTCAudioBridge native bridge + clean audio handoff from CallKit to WebRTC.
</objective>
